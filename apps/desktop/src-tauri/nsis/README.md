# spanseek NSIS process and update policy

The template comes from the official Tauri CLI **2.12.1** tag:

<https://github.com/tauri-apps/tauri/blob/tauri-cli-v2.12.1/crates/tauri-bundler/src/bundle/windows/nsis/installer.nsi>

The downloaded LF source has SHA-256 `dabed59013b1d78b879a1a85bc7f2eed2993b33a9a90cdabe5946de3d3950597`. Converting only LF to CRLF produces an exact full match in the installed `cli.win32-x64-msvc.node` 2.12.1 binary. The original Handlebars expressions are retained; no generated machine paths, package versions, or resource lists are hard-coded into this template. The upstream MIT license is retained alongside it.

The local changes are limited to:

1. Replace the maintenance page's uninstall/reinstall choices with in-place program-file replacement. Setup never executes a legacy uninstaller, whose older process checks may use forced shutdown. The explicit installed uninstaller remains available through Windows Installed apps. This is not a WiX-to-NSIS migration feature.
2. Check the main application and both installed workers during installer/uninstaller initialization and again immediately before their mutation sections.
3. Load the official `installerHooks` extension. `hooks.nsh` replaces Tauri's `CheckIfAppIsRunning` macro with a read-only Restart Manager check. The replacement also prevents Tauri's subsequent stock check from force-closing an application that starts between checks.
4. Keep the legacy `Software\pkms\PKMS` install-location/language key and `Software\Microsoft\Windows\CurrentVersion\Uninstall\PKMS` identity while displaying `spanseek` as product and publisher. New installs use a spanseek program directory; updates keep the chosen original directory.
5. Ship `spanseek.exe` as the only main executable. Guard `spanseek.exe`, both helper names and the legacy main name before replacement or uninstall, and remove legacy `pkms-desktop.exe`, `pkms-worker.exe` and `pkms-inference.exe` explicitly on install and uninstall. Shortcuts still pointing at the legacy main name are retargeted to `spanseek.exe` before that file is deleted. No previously installed application image is retained as an older runtime.
6. Rename the existing standard desktop, Start menu and current-user taskbar `PKMS.lnk` only when its target belongs to this install. Keep `com.pkms.desktop` as the AppUserModelID and notify Shell of the rename. Every final shortcut creation checks the destination too, including when the old standard shortcut was removed or renamed by the user. An unrelated same-name target or write failure exits with 1603; it is not overwritten. An owned existing shortcut keeps its arguments when its target is updated. `brand.nsh` reads and retargets exactly four locations: the standard desktop shortcut, the standard Start menu shortcut, the shortcut inside `$AppStartMenuFolder` when that folder is set, and - for current-user installs - the existing taskbar pin. A shortcut the user created elsewhere, or a user-renamed copy in another folder, is **not** scanned: the legacy main binary is removed only after those four locations are handled, so such a shortcut has to be repointed by the user. No compatibility launcher is kept. This is the exact scope the code implements; do not describe it as "any shortcut". Do not create a new taskbar pin or edit Taskband data.
7. Register PDF OpenWith candidates using a dedicated ProgID and `Applications\spanseek.exe`. Do not write `.pdf`'s default value, `UserChoice`, or call the default-association helper for this registration. Uninstall removes only registration still pointing to this install.

When an application resource is in use, interactive setup asks the user to save and exit normally, then exits with **1618**. Silent `/S` and passive `/P` modes exit with the same code without showing a blocking dialog. If Restart Manager cannot establish that the resource is unused, setup fails closed with **1603**. There is no `RmShutdown` or process termination in the product hooks. A process starting after the last check may cause Windows file replacement to fail; setup must not kill that process to continue.

Program files continue to use explicit install/uninstall lists. [brand.nsh](brand.nsh) owns the scoped branding compatibility changes above; unknown filenames read from registration are not deleted. In-place repair means rerunning the same installer; this does not introduce a Windows Installer repair command, automatic updater, arbitrary schema downgrade, or automatic app-data deletion. Existing workspaces and the default unselected app-data deletion option retain their upstream semantics.

When upgrading Tauri CLI, compare this template to that exact upstream tag and reassess the hook include order, process macro, early checks and explicit file/registry lists. Do not replace this source with `target/release/nsis/x64/installer.nsi`.
