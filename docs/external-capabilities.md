# spanseek 外部接口能力边界（1.0.1）

适用于 spanseek 1.0.1。产品正式名 **spanseek**。本文描述当前实现实际能做什么、不能做什么；不以接口名称代替能力，也不把客户端自由生成的内容算作库内有据事实。

## 1. 三种不同的“生成”

| 能力             | 实际行为                                                                                      | 证据与限制                                                                                             |
| ---------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **有据检索**     | `search` / `read_note` / `list_notes` 返回检索证据、稳定对象 ID、修订、块与摘录               | 当前外部契约的 `search` 只支持 **lexical**；`semantic` / `hybrid` 明确返回 `unavailable`，不会静默降级 |
| **有据报告草稿** | `draft-report --mode evidence` 从已检索证据生成摘录式报告；每段带 `[E编号]`，同时输出来源清单 | 不补写证据外事实；任一引用失效会阻止生成或回查通过                                                     |
| **自由生成**     | 由 MCP/HTTP 客户端自己的模型完成，spanseek 只提供工具结果                                     | spanseek 不把客户端自由生成的句子标记为“有据回答”，也不为它背书                                        |

`draft-report --mode model` 是“模型在冻结证据上写作”：程序要求每个非标题段落包含有效 `[E编号]`，生成后再次回查。它不是无证据自由创作通道。

## 2. 读写边界

- MCP stdio 默认只暴露 `capabilities`、`search`、`read_note`、`list_notes`。默认只读指不修改知识对象、正文修订和提案；允许的只读调用仍会追加 `external_audit_events` 请求元数据。
- `propose_note` 必须由服务启动参数 `--enable-proposals` 显式开启；它只写入 `pending` 提案，不修改正文。
- HTTP 令牌按 `read` / `search` / `propose` / `audit` 分作用域；只读令牌调用提案或审计返回 403。
- 本地 `proposal-get` 用于人工查看；只有 `proposal-apply --confirm` 才把提案应用为新的笔记修订，`proposal-reject --confirm` 只改变提案裁决。
- 外部接口没有“直接保存笔记”“直接改标签”“批量无审写库”方法。

## 3. 访问与安全

| 边界     | 当前事实                                                                                                   |
| -------- | ---------------------------------------------------------------------------------------------------------- |
| 网络监听 | HTTP 仅绑定 `127.0.0.1`；不是公网或局域网服务                                                              |
| 认证     | HTTP 必须 Bearer 令牌；明文只在创建时显示一次，文件只保存 SHA-256                                          |
| 撤销     | 运行中的 HTTP 服务逐请求重读令牌文件，CLI 撤销立即生效                                                     |
| 审计     | 记录请求 ID、令牌 ID/本地主体、方法、作用域、结果、对象 ID、耗时；不存查询、正文、摘录、令牌或路径         |
| 审计写入 | 默认只读不等于数据库文件完全不变：允许的只读请求会追加不含正文/查询词/令牌的审计元数据；知识对象与正文不写 | \n  | 真实库 | 真实库 `我的知识库`（K24）只读；所有写实验使用隔离现场 |
| 未配置   | 模型或密钥未配置时 `model_unconfigured`；无证据时 `no_evidence`；令牌文件损坏时 `unavailable`              |

## 4. 输出与导出

- 报告模板是独立 JSON 文件，支持标题、章节标题、正文段落、引用样式和来源行；未知或缺少必填占位符立即报错。
- `verify-report` 可在交付后重新核对对象、修订、块和摘录；修订变化会把对应引用标为失效，而不是替换为新内容。
- `export-reports` 可批量输出 Markdown、DOCX、PDF；导出前所有报告必须通过引用回查。
- DOCX 保留标题层级、段落、列表文字、引用编号和来源；不保留 spanseek 块 UUID、应用主题或交互编辑能力。
- PDF 使用本机 Microsoft Edge 无头打印；HTML 自包含并禁用后台网络。没有 Edge 时明确失败，不会伪造 PDF。
- 输出文件已存在时整批拒绝，不覆盖用户已有交付物。

## 5. 当前不承诺的能力

- 不承诺外部搜索结果与桌面语义检索完全等价；外部 `search` 当前只有字面检索。
- 不承诺 MCP 客户端生成的自由回答正确；它必须自行展示不确定性，不能把 spanseek 证据当成未引用事实。
- 不承诺 PDF/DOCX 与富文本编辑器逐像素一致；它们是交付格式，不是无损备份。
- 不承诺跨设备同步、多人协作或远程 HTTP；这些不属于 V1.9.6 外部接口。
- 真实模型输出仍须人工核对；其他 MCP 客户端和网络组合的兼容性不作无条件保证。
